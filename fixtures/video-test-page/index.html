ClipHutch — Fixtures

Predictable network requests for testing the extension's detection layer. Open DevTools → Network and load this page; each section explains what should happen.

1. Direct MP4 (h264 + aac)

Loaded as <video src>. Browser fires a media request on page load (preload=metadata).

Expect: popup shows one MP4 entry; size from Content-Length.

2. Direct WebM (vp9 + opus)

Expect: popup shows one WEBM entry with size.

3. HLS — simple VOD (embedded audio, unencrypted)

Click to fire the playlist request. Happy-path download in Session 5.

Expect: popup shows one HLS entry. .ts segments are NOT listed.

4. HLS — master with embedded-audio variants

Master + two variants (1280x720 high, 640x360 low).

Expect: popup may show master + variants (acceptable for v1). All variants downloadable.

5. HLS — master with separate audio rendition

Master uses EXT-X-MEDIA TYPE=AUDIO URI=... referenced by the variant's AUDIO attribute. Detection must succeed; download must reject with SeparateAudioError in Session 5.

Expect: popup detects HLS; download fails with the separate-audio message.

6. HLS — encrypted (AES-128)

Playlist carries EXT-X-KEY METHOD=AES-128 without an IV. Its real encrypted segments use sequence-derived IVs 0 and 1.

Expect: popup detects HLS; download completes and the resulting MP4 plays.

7. HLS — encrypted (AES-128, explicit IV)

Playlist carries an explicit IV and EXT-X-MEDIA-SEQUENCE:5. Both real encrypted segments use the declared IV rather than sequence-derived IVs.

Expect: popup detects HLS; download completes and the resulting MP4 plays.
