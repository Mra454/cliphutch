Welcome to ClipHutch

Web Media Capture · Your browser's media shelf.

ClipHutch watches the network requests your browser makes on web pages and scans image URL attributes already present in page markup so it can list videos and still images it can detect. Click the toolbar icon for a quick view of the current tab, or choose Open Hutch there to keep the workspace beside the pages you browse. Direct-media previews load from the original source URL; click Download to save a file via Chrome's download manager, assemble an HLS or DASH stream into one MP4, or locally convert a WebM file to MP4 before saving. For streams that deliver audio and video separately, the extension fetches both and combines them into one MP4 on your device. Detection, preview display, conversion, and downloading happen on your device. The free tier never contacts a ClipHutch-operated server. If you use a paid license, the extension contacts the ClipHutch license service when you activate or deactivate it and when an existing activation needs a status refresh. A status refresh cannot consume a new device slot. If a refresh fails, ClipHutch may retry on a later opening of the popup or side-panel workspace, but no more than once per hour.

Items you explicitly add to Hutch keep a bounded media/page snapshot and review/run context only in chrome.storage.session. They remain available if the source tab navigates or closes, then clear on browser restart, extension update, or Clear Hutch. If a selected source needs approved replay headers, those headers may be copied into a session-only item lease for no more than 60 minutes; the lease is never used for previews, sent to ClipHutch, written to disk, or included in a capture manifest.

Every normal Capture Pack automatically saves a required, redacted _cliphutch-manifest.json after all media jobs are terminal. An optional CSV is saved only when you opt in. Quick Capture creates no manifest. The files are intentionally written to your Downloads storage and remain there until you delete them.

Permissions

Each permission is requested for a specific technical reason. Detection and downloading happen on your device.

ClipHutch API and host permissions
webRequest Observes network requests, including the request headers the page sent, so the extension can detect media URLs as the page loads them and later replay those headers on its own download fetches. All processing happens on your device.
alarms Schedules a one-shot local cleanup wake for the next selected-item header-lease expiry and for sensitive download-artifact or Capture Pack manifest delivery/cleanup retries. It is not used for tracking or periodic polling. Chrome may deliver an alarm late while the browser is asleep; ClipHutch also reconciles cleanup on the next browser wake.
storage Stores detected media, the selected Hutch media/page snapshot, review/run context, download-job state, and selected-item replay-header leases in browser session memory. Settings, license state, the installation UUID, notices, and rolling free-tier quota timestamps use browser local storage.
sidePanel Hosts ClipHutch's packaged workspace beside the pages you browse so the Hutch and download activity can remain visible when you switch tabs. This permission does not grant additional access to page data.
downloads Saves detected media and a normal Capture Pack's required redacted JSON manifest, plus an optional customer-selected CSV, via Chrome's built-in download manager.
offscreen Used briefly to assemble HLS or DASH audio and video segments, combine separate audio and video tracks, repackage MPEG-TS segments into MP4, or locally convert WebM direct files into downloadable MP4 files. It also creates a bounded local text Blob for a terminal Capture Pack manifest.
declarativeNetRequestWithHostAccess For a selected item that requires specific request headers (such as a Referer the source page sent), a temporary session rule can use that item's bounded header lease. It is limited to extension-initiated XMLHttpRequest/other requests and the selected source's exact scheme, origin, and path scope: the exact source URL for direct-media conversion, or the source origin and directory path for HLS/DASH parts. It never supplies previews. The rule and lease are cleaned when the owning job becomes terminal, an unconsumed item is removed or Hutch is cleared, the lease expires, or the browser session ends. This is the strictly-weakest declarative-net-request variant: it cannot block or redirect requests, only modify headers, and only on hosts you have already granted access to.
http://*/*
https://*/* 		Required for webRequest to observe network requests across HTTP/HTTPS sites and for the content script to scan image URL attributes on HTTP/HTTPS pages. The extension processes network request URLs, request headers it observed when the page loaded, image URL attributes already present in page markup, and the tab URL/title needed to associate detected media with the page.

Local Capture Pack manifests

After every media job in a normal Capture Pack is complete, failed, cancelled, or otherwise terminal, ClipHutch saves _cliphutch-manifest.json during pack finalization. If you select CSV, it also saves _cliphutch-manifest.csv from the same redacted records. Quick Capture creates neither file.

A manifest can contain each item's planned relative path; final basename when Chrome reports one; media kind and bounded width, height, duration, or bitrate metadata when known; capture time and terminal status; bounded public errors; a source page URL with user information, query, and fragment removed; and only the source media host, never the media URL. It never contains captured headers, media URLs or signed queries, Blob URLs, license or installation data, quota or command IDs, raw internal errors, or absolute local paths.

ClipHutch's packaged offscreen document creates a bounded local text Blob and Chrome's download manager saves it. The customer-requested file remains in Downloads until you delete it. One-shot alarms may recover unfinished delivery or cleanup; this uses the existing alarms permission and adds no permission.

Both extensions also need broad host_permissions (http://*/*, https://*/*) so webRequest can observe media URLs across sites. The table above compares API permissions because Chrome lists those separately from broad host access and manifest-declared content scripts. ClipHutch does not request the scripting API. Its content script only scans image URL attributes already present in page markup.

Fewer permissions means a smaller surface for trust. The extension can only see what the listed permissions allow, and you can revoke any of them in chrome://extensions at any time.

What this extension does NOT do

  • Send page or media URLs, page titles, hostnames, filenames, or browsing activity to ClipHutch, analytics services, or a download relay. Preview and download requests still go directly to the original source server.
  • Track usage or include analytics.
  • Read form fields, text content, cookies, passwords, or private page data from the DOM.
  • Provide access to media unless your browser is already authorized to load it.
  • Handle DRM-protected media.

Some HLS streams use standard AES-128 transport encryption. When you start a download, ClipHutch fetches the 16-byte key named by the selected playlist, decrypts the segments on your device, and keeps the key in memory only for that download. If the source refuses the key request, the download fails. ClipHutch does not handle DRM (Widevine, PlayReady, FairPlay) and does not work around logins, paywalls, or other access controls.
